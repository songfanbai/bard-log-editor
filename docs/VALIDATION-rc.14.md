# rc.14 验证记录

环境：Windows、Chrome 156（自动化无头浏览器）、Node.js 24.22.1，file:// 离线页面。测试日期：2026-11-03。

## 已复现与修复

在 rc.13 页面中，用用户提供的带日期 Emote 原文，从“类型与角色”填写新角色原名和服务器，确认后角色头部已创建，正文却仍保留完整姓名及服务器。预览重复姓名；同一文本片段也会进入 Word。用户原文仅用于本机对照，不进入仓库和附件。

现在仅对未确认、未编辑正文的动作，结合用户指定身份及原文调用动作解析来更新分界；不替换正文中的同名词。旧修正保持不变，可主动点“按原文重新识别动作分界”核对并确认。另修复无正文引用数据时打开待确认修正窗口报错。

## 通过

- 20 组新旧格式、无时间、单时间、日期时间、中文标签、有无服务器和正文重复姓名；改名、重新解析、项目恢复。
- 角色原名添加后再清空：自动填入的分界恢复，不产生无效修正。
- 原有角色正文以本人姓名开头时保留；主动编辑的正文不被自动重切。
- 已保存错误修正不静默重写；显式重切、确认、撤销与重做。
- 无服务器动作关联已选的有服务器身份，记录本身不补服务器；显式类型及服务器冲突保护。
- 实际下载项目，再通过文件选择打开；实际下载 DOCX 并解包检查：姓名仅输出一次，正文完整且仍为可编辑文本，保留动作斜体。
- 统一核心和浏览器回归完整跑通：解析、字体、角色、修正、拖入、存储及失败保护、帮助和面板。字体弹层窗口缩放断言首次失败，重跑通过；保留该时序波动记录，不宣称该测试每次稳定。
- 新 ZIP 仅含单文件 HTML、虚构示例、说明及已知限制；从干净解压目录离线运行本轮修正与窗口回归，通过项目和 Word 下载测试。
