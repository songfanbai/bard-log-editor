# rc.15 验证记录

环境：2026-11-03，Windows、Chrome 156 无头浏览器、Node.js 24.22.1；file:// 离线运行。

## 复现与根因

- 在 rc.14 复现：待确认动作 → 操作“记录类型”为动作 → 填写新角色原名 → 确认。类型选择事件错误设置“正文已编辑”保护标志，导致后续角色分界同步被跳过。角色头部与含姓名的完整正文同时渲染。
- 用户此前真实原文也在本机对照复现。该原文不进入仓库、分享包或公开测试。
- 旧项目已保存的错误正文属于历史修正，解析器刻意保留；仅重复添加角色不能安全判断应否覆盖。此次提供结构性核对提示，不静默清理。

## 修复范围

- 类型选择不再伪装成手动正文编辑；真正编辑正文和分界时仍保留保护。
- 仅检查动作正文是否完整等于原始记录去掉时间/类型头后的内容（或完整原文），并结合明确角色身份生成分界建议，不删除普通正文中的姓名。
- 再次添加对应角色且存在该旧修正时，复用“类型与角色”窗口展示建议。只有主动重新识别分界并确认后才修改；取消保持数据。其他无法可靠识别的情形仍可编辑“原始角色名前缀 / 动作分界”及正文，不宣称自动修复所有历史记录。
- “本机副本”与“开始新工作”使用同一尺寸与字体规则，点击功能未变。

## 实际通过

- 20 组新旧格式、可选时间、服务器可空、正文真实重复姓名；每组先选择类型再添加角色，检查正文、改名、重解析及恢复。
- 旧修正提示、取消不改数据、显式修正、撤销重做；修改后连续三次重复添加 → 重新解析 → 项目重开，检查实际预览文本，姓名不重复。
- 已有角色与人工编辑正文保护、无变化确认和输入恢复原值。
- 实际下载项目并由文件选择重新打开；下载 DOCX 后解包 XML，文本与预览一致且可编辑，保留动作斜体。
- 1440/390 像素窗口下两按钮宽高、字号、字重、内边距、对齐一致且无溢出；分别验证开始工作及打开副本入口。
- 完整统一核心与浏览器回归通过：全部类型解析、角色字体、列表/弹层、修正、拖放、存储失败保护、帮助、面板。
- 干净 ZIP 解压目录离线复测本轮两组浏览器测试，项目及 Word 下载通过；包内仅四个允许文件。

未测试其他系统/浏览器、真实中文输入法、桌面 Word 实际字体和分页。历史人工正文不会自动删名前缀；需用户核对后确认。原有不可信项目校验及 30 MiB 导入限制仍存在，继续作为测试版发布。
